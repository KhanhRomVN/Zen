🔍 Diagnostics System Flow

Hệ thống phân tích diagnostics của Zen Extension

📊 Flow Chính: getDiagnostics()

1
Check Non-Code File
Kiểm tra file có phải code không (dựa vào extension: .md, .txt, .json, v.v.)
❌ Nếu không phải code file → return { diagnostics: [] }
⬇️
2
ensureFileOpened()
Kiểm tra kích thước file:
• File > 100KB → return { success: false } (tránh crash)
• File đã mở → return { success: true, alreadyOpen: true }
• File chưa mở → Mở file và return { success: true, alreadyOpen: false }
⬇️
🔀 Decision: File opened successfully?
❌ NO: Return { diagnostics: [], skippedReason: "file_too_large" }
✅ YES: Tiếp tục → waitForDiagnostics()
⬇️
3
waitForDiagnostics()
Đợi Language Server phân tích file
Xem chi tiết ở phần "Wait For Diagnostics Logic" bên dưới
⬇️
4
Return Diagnostics
Lấy diagnostics từ VSCode cache → Filter chỉ Error & Warning → Return

⏱️ Wait For Diagnostics Logic

🚀 EARLY RETURN: File đã mở + có diagnostics
Điều kiện: alreadyOpen === true && diagnostics.length > 0
Hành động: Return ngay lập tức (không cần đợi events mới)
Lý do: Diagnostics đã có sẵn từ lần phân tích trước
⬇️
1
Listen to Diagnostic Events
Subscribe to vscode.languages.onDidChangeDiagnostics
Đếm số events (eventCount) và track lastEventTime
⬇️
2
Poll Loop (mỗi 500ms)
Check diagnostics và quyết định return dựa trên các PRIORITY bên dưới
⬇️
✅ PRIORITY 1: Events đã settled
Điều kiện:
• eventCount > 0 (LS đã chạy)
• timeSinceLastEvent >= 300ms (đợi cache update)

Case 1A: Có diagnostics
diagnostics.length > 0 → Return ngay
Case 1B: File sạch (không có diagnostics)
Return khi: eventCount >= 3 HOẶC timeSinceLastEvent >= 3000ms
Lý do: Đủ events hoặc LS đã finished (lâu không có event mới)
⚠️ PRIORITY 2: No events timeout
Điều kiện: eventCount === 0 && elapsedTime >= 15000ms
Hành động: Return với diagnostics hiện có (có thể rỗng)
Lý do: LS không phản hồi (Extension Dev Host isolation hoặc LS crash)
PRIORITY 3: Max timeout
Điều kiện: elapsedTime >= 30000ms
Hành động: Return với diagnostics hiện có
Lý do: Fallback nếu LS quá chậm

⚙️ Configuration Constants

Constant Giá trị Mô tả
MAX_FILE_SIZE_BYTES 100 KB Giới hạn kích thước file để mở trong editor
DEFAULT_DIAGNOSTICS_MAX_WAIT_TIME_MS 30,000 ms (30s) Thời gian tối đa đợi LS phân tích
NO_EVENT_TIMEOUT_MS 15,000 ms (15s) Timeout khi không nhận được event nào (LS không respond)
DIAGNOSTICS_POLL_INTERVAL_MS 500 ms Tần suất check diagnostics trong poll loop
CLEAN_FILE_EVENT_THRESHOLD 3 events Số events cần thiết để xác định file sạch
EVENT_SETTLE_DELAY_MS 300 ms Thời gian đợi sau event cuối để đảm bảo VSCode cache đã update
LS_FINISHED_THRESHOLD_MS 3,000 ms (3s) Nếu không có event mới sau khoảng này → coi như LS đã finished

💡 Các Trường Hợp Sử Dụng

✅ Trường hợp 1: File có errors/warnings
1. File mở → LS phân tích → Emit events
2. Sau 300ms từ event cuối, có diagnostics
3. Return ngay với list errors/warnings (thời gian: ~1-2s)
✅ Trường hợp 2: File sạch (không có lỗi)
1. File mở → LS phân tích → Emit 2-3 events
2. Sau 3s không có event mới → LS finished
3. Return empty diagnostics (thời gian: ~3-4s)
✅ Trường hợp 3: File đã mở trước đó
1. Check alreadyOpen === true
2. Đã có diagnostics trong cache
3. Return ngay lập tức (thời gian: ~0ms, không cần đợi)
⚠️ Trường hợp 4: LS không phản hồi
1. File mở nhưng không nhận được event nào
2. Sau 15s timeout → Return với skippedReason
3. Thông báo: "LS không phản hồi kịp"
⚠️ Trường hợp 5: File quá lớn
1. Check size > 100KB
2. Skip diagnostics ngay (không mở file)
3. Return với skippedReason: "File quá lớn"

🚀 Tối Ưu Performance

1. Early Return cho file đã mở
Tránh đợi không cần thiết khi diagnostics đã có sẵn
2. LS Finished Detection
Phát hiện LS đã xong (3s không có event) → không chờ đủ 3 events
3. File Size Check
Skip file lớn ngay từ đầu → tránh crash + tốn tài nguyên
4. Multiple Priority Levels
Xử lý theo priority → return sớm nhất có thể
